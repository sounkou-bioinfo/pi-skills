# Orientation pilot: scope and evidence

This is a bounded manual exercise in the working-tree change based on `0364b77`,
not an Astra comparison, independent model-routing test, or proof of retained
human understanding. No repository-specific skill was retired.

| Case | Exercise and evidence | Work deliberately not implied |
|---|---|---|
| README capability correction | The authored source is `README.Rmd`, not its generated `.md`. The instruction-only stage ran render/consistency, package/link checks and the Pi skill loader without a runtime suite. | No architecture tour or native ABI tests for the prose correction. Later runtime changes require their own stronger gate. |
| Memory lifecycle and scope change | Applied the [orientation workflow](../skills/project-orientation/SKILL.md) to distinguish graph labels from actual scoped retrieval/compression, and a recorded checkout from verified runtime evidence. [Memory regressions](../extensions/memory/memory.test.ts) exercise current slots, interleaved forests, old snapshots, bounded context and fake-hook project switching. | No claim that fake hooks are real Pi sessions, that summaries preserve every nuance, or that an installed extension changed with this checkout. |
| Rducks ABI change — planning only | Reviewed the retained [Rducks contract](../skills/rducks-development/SKILL.md): exact artifact identity, no silent plan/ABI substitution, R-thread/SEXP ownership, distinct direct/worker transports and repository-required handoff gates. Orientation should recover these constraints, not replace them. | No Rducks implementation/build or native ABI behavior was exercised. This row is route/constraint review only. |

The useful distinction retained here is that **scope, applicability and sharing
are different decisions**. A label alone did not isolate the former memory tree;
a checkout receipt does not identify a loaded artifact; local storage does not
decide whether a lesson belongs in shared instructions. The new memory namespace
preserves old evidence rather than silently assigning it a new meaning. Review
also exposed two concrete counterexamples: an old label can collide with a new
scope, and filtering after cross-protocol version resolution can hide a valid
current fact. The regressions now require namespace isolation before promotion
and independent version slots, not merely fewer returned rows.

A real effectiveness pilot still needs comparable task outcomes: unnecessary
reconstruction, missed constraints, accepted semantic changes, verification and
human control, with exact host/model versions. Shorter prompts, loaded skills and
green storage tests are not substitutes. See [coverage and gaps](../TEST_PLAN.md).
